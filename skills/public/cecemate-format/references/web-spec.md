# cecemate-format · 网页规范

HTML 制品是可独立阅读的 CeCeMate 报告页。它服务于信息理解和事实核对，而不是展示炫技动效或套用同一张模板。此文件只影响 HTML；DOCX/PDF 继续遵循 [doc-spec.md](doc-spec.md) 和既有渲染器。

## 1. 生成方式与必备骨架

HTML 默认由模型直接生成完整页面，而不是受 `content.json` 固定模块限制。根据内容选择最能表达重点的组织方式：数据密集时突出指标、表格和静态 SVG；研判密集时突出结论、证据与风险清单；时间事件密集时突出时间线。不要为了“页面完整”虚构模块。

每个页面都必须保留以下骨架，顺序不可调换：

```text
header（行业洞察 Logo）
main（主题内容）
  └── 最后一个 section.disclaimer（篇尾免责声明）
footer（行业洞察 Logo、来源或版本信息）
```

Logo 使用技能目录的 `assets/logo.png`，可用相对路径或与该文件字节一致的内联 base64。页头高 34px、页脚高 22px，透明原图、等比缩放、不可弱化或替换为文字。页头用白底和 1px 底部描边；页脚用白底和 1px 顶部描边。Logo 周围留白至少为其高度的一半。

`main` 的最后一个 `section.disclaimer` 必须逐字包含：

> 内容由 AI 生成，请核实重要信息

长版文案使用：

> 内容由 AI 生成，请核实重要信息。本页由 CeCeMate 智能体生成，可能存在遗漏、滞后或理解偏差；本页不构成决策依据，据此操作风险自担。

免责声明通栏、浅灰底、上边线、无圆角无阴影；不得折叠、隐藏或放入页脚。`scripts/check_web_required.py` 只强制检查 Logo 与上述免责声明。

## 2. 设计方向

先为页面确定一个信息重点，再设计主次关系。页面应该具有明确的阅读路径，而不是把标题、指标、图表、表格、结论平均铺开。

优先级如下：

1. **数据先于装饰**：每个颜色、分区、图形都应帮助理解数据或结论。
2. **可核对**：数字有单位，图表有口径和时间范围，推断与原始事实可区分。
3. **一色一义**：蓝色表示强调和主操作；绿、红、橙分别只表示正向、风险、关注；灰色承担信息层级。
4. **描边分层**：用浅灰页底、白色内容区和 1px 描边建立层次，不使用卡片阴影。
5. **克制但不模板化**：允许内容驱动的栅格、大小对比和留白；禁止渐变、自动轮播、视差、鼠标跟随、emoji 和无信息价值的装饰。

避免通用“AI 看板”外观：不要用大面积蓝紫渐变、漂浮玻璃卡、彩色标题竖线、实底彩色标签、圆角过大的胶囊或为好看而堆叠图标。标签是分类信息，不是按钮。

## 3. 品牌令牌

用 CSS 变量集中定义颜色和尺寸；正文中优先引用变量。推荐颜色：

| 用途 | 令牌与色值 |
| --- | --- |
| 主强调 | `--blue-600: #016ADE` |
| 强调深色 | `--blue-700: #004FC1` |
| 强调浅底 | `--blue-100: #E8F3FF` |
| 页面底 / 卡片底 | `--gray-200: #F5F8FB` / `--gray-000: #FFFFFF` |
| 描边 / 分割线 | `--gray-400: #E0E6EB` / `--gray-300: #EDF2F8` |
| 标题 / 正文 / 辅助文字 | `--gray-1200: #282B2E` / `--gray-1000: #626A71` / `--gray-900: #7B838C` |
| 正向 / 风险 / 关注 | `--green-600: #00B877` / `--red-600: #E62C3B` / `--orange-600: #FF7400` |

蓝色是强调，不是页面底色；应以白灰为主。状态颜色必须配合文字、箭头或符号，不能仅靠颜色传递含义。

字体栈使用：

```css
"Source Han Sans CN", "Noto Sans CJK SC", "PingFang SC",
"Hiragino Sans GB", "Microsoft YaHei", sans-serif
```

字号建议：主标题 32px/600，章节标题 20px/600，小节 16px/600，正文 14px/1.75，辅助说明 12px，脚注最小 11px。中文正文行长控制在约 38 字；长段落应分段或分栏，不要把宽屏整行文字拉得过长。

间距以 4px 为基数。推荐内容版心最大 1200px，左右 28px，区块间 20px，卡片间 16px。标签圆角 2px、卡片 6px、容器 8px；描边均为 1px；全页 `box-shadow: none`。

## 4. 内容编排

页面可自由组合下列模式，按内容选择，不能把它们误读成必选模板：

- **标题与摘要**：一个页面只有一个 `h1`；导语先给判断或范围，再给阅读线索。
- **指标区**：2–4 个指标适合等宽卡；单一关键数值适合带状强调区，不必硬凑四卡。
- **数据表**：最多约 8 列；表头浅灰底；数值右对齐并使用等宽数字；只使用横向分割线。
- **结论与发现**：较长研判可采用主文 + 关键发现的双栏；关键发现应是可核对的短句。
- **风险或主体清单**：使用描边白卡或矩阵；卡内先状态、后名称、再说明。
- **时间事件**：时间线按时间排序，节点和日期清晰；内容不足时不要勉强做时间线。
- **图形**：优先静态 SVG 或 CSS/HTML 图形。图形必须有标题、数据口径和时间范围；使用图表时选择与关系相符的类型，避免 3D、双 Y 轴和超过六段的饼图。
- **数据说明**：当数据来源、口径、覆盖范围或局限会影响理解时，放在结论或篇尾免责区前。

图形不是装饰。时间趋势适合折线，类别比较适合柱/条，构成占比适合不超过六段的环形；没有可靠数据时明确写“暂无公开数据”及原因，不画空坐标轴。

## 5. 组件细节

- 指标卡：浅灰底或白底 + 1px 描边；标签、数值、单位、变化信息分三层表达。数值 26px 左右，单位紧随其后；正负变化同时给符号和文字。
- 标签：透明底、1px `currentColor` 描边、2px 圆角；不要把标签做成实底彩块。
- 提示块：白底描边，通过小型描边图标和文字区分信息、关注、风险；不用彩色左竖条。
- 表格：单位写入表头；缺失值写“暂无公开数据”；合计行使用上边线和字重，而不是色块。
- 操作：网页默认只读。确需下载或切换时，主操作不超过两个，按钮高度约 32px，hover 只改变颜色，不位移、不加阴影。

## 6. 文字、响应式与无障碍

数字使用千分位；万/亿保留一位小数；正负显式写 `+` / `−`，百分点用 `pct`。日期在同一页面内统一为 ISO 或中文日期。非事实判断应写明“据…推算”或“以…口径估算”，避免营销词。

在 1024px 以下将双栏转单栏，在 720px 以下将指标卡改为一至两列；表格可横向滚动，但应提示用户。打印时取消 sticky，避免卡片和图形跨页断裂。

页面必须设置 `lang="zh-CN"`、viewport、语义化 `header/main/section/footer` 和连续的标题层级；Logo 有非空 `alt`；静态图形给 `aria-label` 或邻近的文字数据说明。仅对交互元素提供焦点样式，所有非必要动效均应省略。

## 7. 人工复核

在运行 Logo/免责声明校验后，人工检查：信息重点是否明确、数据单位和来源是否完整、颜色是否符合语义、移动端表格和图形是否可读、是否存在大面积空白或拥挤、以及页面是否仍像“一份报告”而非通用产品后台。视觉问题应重排内容，不要通过添加装饰解决。
