# CeCeMate 文档产出物 UI/UX 标准规范

| **生效** | **适用范围** | **版心** | **正文** |

## 01 适用范围与边界

规范管四件事：**纸张与版心**、**字体字号与编号**、**表格与图的规整**、**必须出现且不可删的品牌与声明**。不管：内容观点、数据准确性、章节逻辑。

| 维度 | 文档（本规范） | 网页（另见网页规范） |
| --- | --- | --- |
| 版心 | 固定 17.18cm，随纸张 | 1200px 弹性版心 |
| 字号单位 | pt，禁用 px | px |
| 层级手段 | 字号 + 编号 + 段间距 | 卡片 + 描边 + 底色 |
| 信息密度 | 高，允许长表与长段 | 低，图表优先 |
| 强制出现 | 行业洞察logo（封面 + 页眉）、免责（篇尾 1 处）、页码 | 行业洞察logo（页头 + 页脚）、免责（篇尾 1 处） |

> **不要把网页直接打印成文档。** sticky 页头、卡片描边、图表交互在纸面上全部失效，且没有页码、没有页眉行业洞察logo、没有可更新的目录。需要纸面交付时，必须按本规范重新排版。

## 02 文档设计原则

| 原则 | 含义 | 落地判据 |
| --- | --- | --- |
| **一纸到底** | 版式在 A4 上闭环，不依赖屏幕 | 打印后无内容被裁、无跨页错位、页码连续 |
| **一色一义** | 蓝色只表示“这是标题” | 标题全蓝、正文全灰；正文无蓝色、标题无第二色 |
| **可编辑** | 交付物能被继续修改 | 真样式、真表格、真域代码；无图片化文本、无文本框 |
| **可追溯** | 每个数字有来源 | 表有表题与来源，图有图题与口径 |
| **编号唯一** | 结构靠编号，不靠样式猜 | 一、/ 1.1 / 1.1.1 连续且不跳级 |
| **克制** | 不用装饰制造层级 | 无艺术字、无渐变、无底纹卡片、无 emoji |

## 03 品牌与行业洞察logo（强制）

文档的品牌标识出现两次：**封面顶部**与**每页页眉**。两次都是强制项，任何页数、任何导出格式都不许删。

![行业洞察logo](../assets/logo.png)

| 位置 | 高度 | 次数 | 约束 |
| --- | --- | --- | --- |
| 封面 | 1.10cm | 1 | 置于版心顶部，左对齐或居中二选一，全文档统一；与标题间距 ≥ 2.5cm |
| 页眉 | 0.55cm | 每页 | 页眉高 1.2cm，行业洞察logo 垂直居中；右侧写文档名（9pt gray-900）；页眉下 0.5pt gray-400 细线 |
| PDF 书签 / 封面页脚 | ≥ 0.5cm | 1 | 可选；若出现不得小于 0.5cm |

| 原始尺寸 | 宽高比 | 封面高 | 页眉高 |
| --- | --- | --- | --- |
| 2529×480 | 5.27 : 1 | 1.10cm | 0.55cm |

资产唯一来源为 `assets/logo.png`（透明底 PNG，即行业洞察logo；文件名保持不变）。嵌入 Word 时必须**等比缩放**：先定高度，宽度由比例推导（封面 ≈ 5.80cm、页眉 ≈ 2.90cm），不得手动拉伸到某个宽度。

> **放 logo 的段落不能设固定行距。** 正文样式是固定 17.3pt，若 logo 段落又写一个更小的固定行距（如 14pt），Word / WPS 会按行高把图裁掉一截——封面只剩 logo 下半截就是这么来的。该段行距必须为**单倍**（`w:lineRule="auto"`），或固定值 ≥ 图片高度；生成后必须人工复核这一条。

> **行业洞察logo 必须放在页眉里，不能放在正文流中。** 放在正文里的图片会随内容换页而位置漂移，第二页起就消失；放在页眉里才能保证“每页都有”。同理，**禁止用文本框承载行业洞察logo**——文本框在 WPS / Google Docs / Pages 之间必然跑位。

### 3.1 禁令

- 不得删页眉、不得设“首页不同”把封面行业洞察logo 一起取消（封面单独一节，行业洞察logo 手动放）。
- 不得改色、加底色、加深色描边、加阴影、加深色页眉色带（页眉背景必须白）。
- 不得用文字“XX 出品”替代行业洞察logo；不得用低分辨率截图或二次压缩的 JPG。
- 不得让行业洞察logo 被页眉边距裁切；四周留白 ≥ 行业洞察logo 高度的 0.5 倍。
- 不得因“页面太满”而缩小到 0.4cm 以下——此时应减内容，不是减行业洞察logo。

## 04 版式基础

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 纸张 | A4 纵向 210×297mm | 横版仅在宽表场景使用，且需整篇统一 |
| 页边距 | 上 2.40 / 下 2.40 / 左 1.91 / 右 1.91 cm | 左右边距决定版心，不得为“多放内容”压到 1.5cm 以下 |
| 版心 | 17.18 × 24.90 cm | 所有正文、表格、图片不得超出；表格与图片宽度均按版心自适应 |
| 页眉 | 1.20 cm | 距上边界 1.20cm |
| 正文行距 | 1.65 倍（≈17.3pt） | 固定值 17.3pt 优于倍数，避免字体替换后行距跳动 |
| 段落间距 | 段后 6pt | 不用空行制造间距；段前 0 |
| 首行缩进 | 2 字符（21pt / 0.74cm） | **所有正文段落统一缩进**，用 `firstLineChars=200` 而非敲空格；标题、表题、来源、免责、目录、表格单元格不缩进 |
| 对齐 | 两端对齐 | 末行左对齐；禁止强制分散对齐 |

版心是硬边界。表格宽度取版心宽（\`w:tblW type="dxa"\` ≈ 9739 twips），**列宽由 \`w:tblGrid\` 一次性定死、布局用 \`fixed\`**，表头与每一行数据共用同一组列宽；只给比例不给 \`tblGrid\`、或只给表头设列宽，Word 就会按内容重算，表头与数值列由此错开（见 §10.1）。**不要用 \`pct 100%\`**：Word 会在百分比宽度之外再加左右单元格内边距（各 80 twips），表格外扩约 3mm，右边界越过正文。图片同理：宽度取 \`min(原始宽度, 版心宽)\`，等比缩放，小图不放大。

## 05 字体与字号阶梯

标题用黑体，正文用宋体——这是中文正式文档的阅读惯性，也是打印时最稳的组合。全文档只用两款字族，不再引入第三款。

| 层级 | 字体 | 字号 | 字重/行距 | 用途 |
| --- | --- | ---: | ---: | --- |
| 封面主标题 | 黑体 | 26pt | 加粗 / 1.35 | 全篇唯一，不超过两行 |
| 封面副标题 | 黑体 | 14pt | 加粗 / 1.6 | blue-600，与主标题同族、轻一档 |
| 章标题 h1 | 黑体 | 16pt | 加粗 / 1.5 | “一、×××”，段前 0（新页起）段后 10pt |
| 节标题 h2 | 黑体 | 13pt | 加粗 / 1.5 | “1.1 ×××”，段前 14 段后 6pt |
| 子节 h3 | 黑体 | 11.5pt | 加粗 / 1.55 | “1.1.1 ×××”，段前 10 段后 4pt |
| 正文 | 宋体 | 10.5pt | 常规 / 1.65 | 两端对齐；**首行缩进 2 字符** |
| 表格正文 | 宋体 | 9pt | 常规 / 1.45 | 表格内不换行字号，超 9pt 会导致宽表溢出 |
| 表头 | 黑体 | 9pt | 加粗 / 1.45 | gray-100 底 |
| 图/表题注 | 黑体 | 9pt | 加粗 / 1.4 | “表 1 ×××”居表上，“图 1 ×××”居图下；**取灰 gray-1000** |
| 来源/注释 | 宋体 | 8.5pt | 常规 / 1.5 | gray-900；紧跟表格或图下方 |
| 免责声明 | 黑体 | 9pt | 加粗 / 1.45 | 只在篇尾出现一次；页脚不再放声明 |

> **各级标题全部加粗，不靠颜色或字号“暗示”层级。** 四级指封面主标题、章、节、子节；封面副标题虽不参与编号，但属标题块，同样加粗。字重只有“加粗 / 常规”两档——正文、表格正文、来源注释用常规，其余标题与表头用加粗回退到 600 以上，跨 Word / WPS / Pages 都不会丢。

> **中文字体必须设三处。** DOCX 里 `ascii`、`hAnsi`、`eastAsia` 是三个独立属性。只设 `ascii` 时，中文会回退成默认宋体，标题看起来“没生效”——这是 Word 排版最常见的返工原因。

### 5.1 标题用色：标题取品牌蓝，图表说明取灰

一至四级标题用品牌蓝，表题与图题属**图表说明**、不属标题，一律取中性灰；正文与表格文字保持中性灰。**蓝色在文档里只属于标题层级**——正文里的强调只用加粗、不带颜色，免得普通句子被读成标题。

| 层级 | 字重 | 色值 | 理由 |
| --- | --- | --- | --- |
| 封面主标题 26pt | 加粗 | blue-800 `#0043A0` | 最大字号，用最深一档压住整页 |
| 封面副标题 14pt | 加粗 | blue-600 `#016ADE` | 主色，与主标题同族但轻一档 |
| 章标题 h1 16pt | 加粗 | blue-700 `#004FC1` | 层级最高，比主色深一档 |
| 节标题 h2 13pt | 加粗 | blue-600 `#016ADE` | 主色 |
| 子节 h3 11.5pt | 加粗 | blue-600 `#016ADE` | 与 h2 同色，靠字号与编号区分 |
| 表题 / 图题 9pt | 加粗 | gray-1000 `#626A71` | 图表说明，**不占蓝色**；灰一档退到数据之后 |
| 正文 / 表格正文 | 常规 | gray-1100 `#3F4449` | 纸面正文用深灰，比说明深、比纯黑柔和 |
| 来源 / 注释 / 页眉 | 常规 | gray-900 `#7B838C` | 全篇最轻一档 |

四条硬约束：

- **蓝色标题上不许再叠底纹、下划线、色块。** 颜色已经承担了层级，再加装饰就成了宣传单页。
- **不许按章节分配不同蓝色**（第一章深蓝、第二章亮蓝）。层级只随字号与位置变化，不随内容变化。
- **图表说明不取蓝。** 表题、图题若也用蓝，读者会把它读成“下一节的标题”；取灰后，“标题 / 数据 / 说明”三级一眼分开。
- **灰度检查**：blue-800 转灰约 27%，正文 `#3F4449` 约 24%，两者在黑白输出中几乎同调——所以**黑白可辨靠的是字号、加粗与编号**（16pt 加粗 vs 10.5pt 常规），颜色只是彩色输出时的加成，不是唯一标识。

落 Word 时改 `Heading 1–3` 样式的字体颜色与加粗即可，不要逐段手刷；封面主副标题、表题是独立段落格式，单独设。色值以本节定义的 `blue-800`、`blue-700`、`blue-600` 与 `gray-1000` 为准。

## 06 封面规范

封面单独成节（section），不设页眉页脚，但**行业洞察logo 必须放置**。自上而下六个区块，垂直节奏固定。**免责声明**统一在篇尾。

> **封面的判据不是“有没有 logo”，而是“封面是否独占一页”。**封面必须单独成节并以“下一页”分节符收尾：封面页无页眉、无页脚、无页码，摘要与目录不得与封面同页。少一次分节符，封面就会和摘要挤在一页——这是“看起来没有封面”最常见的来源，由 D32 校验。

| 序 | 区块 | 内容与规格 |
| --- | --- | --- |
| ① | 行业洞察logo | 高 1.10cm，左对齐或居中（全文统一）；距下方 2.5cm |
| ② | 分隔线 | 1px（0.5pt）gray-400，通栏版心宽 |
| ③ | 主标题 | 26pt / **加粗** / 行高 1.35，**blue-800**，两行以内 |
| ④ | 副标题 | 14pt / **加粗** / 行高 1.6，**blue-600**；距下方 2.0cm |
| ⑤ | 元信息 | 2–4 行，行距 1.9，每行“键：值”，gray-1100；必含报告主体、周期、口径、编制单位 |
| ⑥ | 日期 / 版本 | 页脚位，9pt gray-900，左日期右版本 |

封面排版示例：

```text
行业洞察人工智能企业风险研究报告v1.0


报告期：2026-10-20 至 2026-11-12
数据口径：企业风险数据
CeCeMate 自动生成

2026-11-18
```

主标题不加书名号、不加副标题式冒号；副标题一句话说明范围与方法。元信息四行缺一不可——报告主体、周期、口径、编制单位是文档可追溯性的最低要求。

## 07 页眉与页脚

页眉承担品牌，页脚只承担定位（页码）。页眉是硬性要求，不许为了“干净”而清空；页脚**只放页码**，不放声明、不放文档名、不加横线——一页里第二句重复的话会削弱正文，而声明已在篇尾给出。

正文页自上而下：**页眉（行业洞察logo + 文档名）→ 章标题 → 节标题 → 正文 → 表题 → 表格 → 表源&#x20;**。

正文页排版示例：

```text
一、整体表现
1.1 核心指标
大促期间全渠道支付成交额 18,426.6 万元，同比增长 23.8%，增速高于行业均值约 9 个百分点。
（此后紧接表 1，版式见下方示例）
```

正文页示意：页眉行业洞察logo（0.55cm）+ 文档名；页脚只有右对齐的页码域。

**页眉**

| 元素 | 规则 |
| --- | --- |
| 行业洞察logo | 高 0.55cm，左侧，垂直居中；与页眉下边线留白 ≥ 0.15cm |
| 文档名 | 9pt gray-900，右侧；超长时截断不换行 |
| 下边线 | 0.5pt gray-400，通栏版心宽，不延伸至纸边 |

**页脚**

| 元素 | 规则 |
| --- | --- |
| 无 | **一律留空**：不放免责声明、不放文档名、不加横线、不放“内部资料”等字样 |

页脚留白不是浪费：翻页时视线不被打断。

正文页中的表 1 示例——表题居中居表上（9pt/600），来源左对齐居表下（8.5pt gray-900）：

表 1　经济核心指标情况

| 指标 | 本期 | 同比 | 目标达成 | 状态 |
| --- | ---: | ---: | ---: | --- |
| 融资额（万元） | 18,426.6 | +23.8% | 106.4% | 达成 |
| GDP（元） | 286 | +4.1% | 98.6% | 接近 |
| 同比 | 3.6% | −0.9pct | — | 改善 |

数据来源：行业洞察中台，统计截至 2026-11-12

封面节设为“首页不同”并清空页眉页脚（页码不从封面起算）；正文节取消“首页不同”，确保每页都有行业洞察logo 与页码。页码起始值设为 1，与目录一致。

## 08 标题与编号

文档结构靠编号表达，不靠字号猜。编号规则固定三级，超过三级说明内容该拆章。

| 层级 | 格式 | 规则 |
| --- | --- | --- |
| 章 h1 | 一、企业概况 | 中文数字 + 顿号；从“一、”连续编号；**每章新起一页**（长文档）或连续排（≤10 页短文档） |
| 节 h2 | 1.1 企业价值评分 | 阿拉伯数字 + 点 + 空格；章内从 .1 连续；章号与 h1 序号对应 |
| 子节 h3 | 1.1.1 评分构成 | 三级编号；同一节内连续 |

- 编号与标题文字之间用**一个空格**，不用顿号、不用冒号、不用制表符对齐。
- 标题末尾不加句号；标题内不使用括号补充说明（应下沉为正文）。
- 标题必须设为“与下段同页”（keep-with-next），避免标题孤立在页底。
- 不使用自动编号列表充当标题——导出 PDF 后编号会丢失层级。
- 禁止跳级：h1 下不得直接出现 1.1.1。

## 09 正文

正文承担论证，不承担装饰。段落、数字、标点三件事写对，文档就成立；这三件事错了，字号与配色再准也不像正式文件。

### 9.1 段落与缩进

每段只讲一件事，首句直接给结论；一段控制在 3–6 行（约 80–180 字），超过 200 字必须拆段。首行缩进 2 字符由「正文段落」样式统一给出（**firstLineChars=200**），不得用空格或全角空格顶位。

段间距只用段后 6pt，**不得插空段落制造间距**；同页出现连续两个空段落即判排版缺陷（D31）。段落内部不得用 Shift+Enter 硬换行，换行交给排版引擎；段落首尾不得留空格。

正文两端对齐、末行左对齐；不得用分散对齐把短行拉开，也不得为对齐在句中塞空格。

### 9.2 分页与留白（空白页治理）

分页是排版动作，不是排版装饰。全文只允许三处强制分页：**封面之后、摘要之后、目录之后**。正文各章之间默认连续排，章标题以段前间距区分层级（h1 连续排时段前 24pt、段后 10pt；新页起时段前归 0）；仅当单章内容 ≥ 1.5 页且全文超过 20 页时，才允许章前分页。§08 所述“长文档每章新起一页”，以本节判据为准。

**禁止空白页与半空页。**除最后一页外，每页的有效内容（不含页眉页脚）应占版心高度 ≥ 35%，低于 25% 即为缺陷（D30）。章末页不得只剩 ≤ 2 行正文（孤页）；出现时压缩本章表述或调整图表位置，不得靠加空行把内容推到下一页。

不得在同一处同时使用「空段落 + 分页符」或「空段落 + 段前分页」制造新页——这是空白页最直接的来源。表题、图题与其图表必须同页（keep-with-next）；表与图不得单独占一页，除非整页图版并标注“图版”。

### 9.3 数字、单位与标点

统计值、比例、编号用阿拉伯数字；表述性数量用汉字（“一季度”“三分之一”）。千分位用半角逗号，百分数用半角 %，区间用一字线“—”，同比写作 +39.5% / −0.9pct。

数值与单位之间留 1 个空格（10.5 pt、20 万 P），百分号与摄氏度紧贴数值。正文用全角标点；机构缩写首次出现给出全称，如“世界人工智能合作组织（WAICO）”。

### 9.4 强调与列表

强调只用加粗，不叠加颜色、下划线、斜体，一段内加粗不超过 2 处。并列项 ≥ 3 条用编号列表，≤ 2 条写成句内并列；列表项句式一致，末尾统一不加标点（完整句除外）。不使用 emoji 与装饰性符号分隔。

## 10 表格规范

文档的信息主体是表格。表格越规整，文档越像正式文件。

| **项** | **规则** |
| --- | --- |
| 表题 | 表上方居中，“表 N 标题”（编号与标题间用全角空格）；9pt/加粗，**gray-1000 不取蓝**；**表题不与表格分离** |
| 来源 | 表下方左对齐，8.5pt gray-900，“数据来源：×××”；无来源不得出表 |
| 线框 | 全框线 0.5pt gray-400；表头上边线 0.75pt gray-600、下边线 0.75pt gray-600；外框 0.75pt gray-600 |
| 表头 | gray-100 底；不必重复加粗（字重 600 已足够）；**跨页必须重复表头**（tblHeader） |
| 表宽 | **自适应版心**：\`w:tblW type="dxa"\`，值 = 版心宽（17.18cm → 9739 twips），由页面宽减左右边距算出；换纸张、调边距都跟着走 |
| 列宽 | **列宽只认一份来源**：把各列 twips 一次算好写进 \`w:tblGrid\`，**表头与每一行数据的 \`w:tcW\` 都取同一组值**，尾列吸收取整误差使合计 = 版心宽 9739；布局用 \`w:tblLayout type="fixed"\`，禁止 \`autofit\` |
| 对齐 | **表头与同列数据同向对齐**：文本列表头左对齐、数值列表头右对齐，禁止“表头居中、数据左 / 右对齐”的错列；数值右对齐 + tabular-nums；单位写在表头括号内 |
| 单元格 | 上下内边距 2pt、左右 4pt；竖向居中；**行不跨页断开**（cantSplit） |
| 合并 | 仅允许两层分组表头；禁止纵向合并制造“分类感”，改用分组小标题行 |
| 长表 | 超过 1 页的表，在表题后加“（续）”，并重复表头；禁止把表拆成两张无关联的表 |
| 键值表 | 首列写标签（gray-100 底、宽 22%），不设表头行，用于“工商信息”“文档属性”类内容 |

> 定死列宽不等于“随便压”。列宽仍要按内容给足：首列能放下最长名称、数值列能放下最长数字（含千分位与百分号）。布局改成 **fixed** 后，内容超出不会自动改列宽，只会挤成多行或压到行尾——所以列宽必须在排版之前按最长一条内容量一遍，再写进 \`tblGrid\`。

## 11 图、公式与代码

### 11.1 图

- **宽度自适应**：取 `min(原始宽度, 17.18cm)`，超出等比缩小、小图不放大；缩排用等比缩放，禁止整页缩放 0.9 打印——那会让全文页数错乱。
- 并排两图各占版心一半（中间留 0.4cm 水槽），图宽按 `(17.18 − 0.4) ÷ 2` 计算；三图及以上改为上下排列，不做九宫格。
- 图所在段落行距必须是**单倍**，不得用固定行距（会裁切图片，见 §03）。
- 图题在图**下方**居中：“图 N　标题”，9pt/加粗，gray-1000（与表题同一规格）；图下如有来源，另起 8.5pt 行。
- 插图必须为矢量导出（SVG→EMF/PDF）或 ≥200dpi 位图；不得直接截屏（带滚动条、带阴影、带他人水印）。
- 图表配色沿用网页规范的 8 色板与线宽，保证同一份内容两种形态观感一致。
- 图与正文之间上下各留 6pt；图不得单独占一页（除非整页图版，需标注“图版”）。

### 11.2 公式

- 用 Word 原生公式对象，不用图片；行内公式与文字基线对齐，独立公式居中并右侧编号 (1)(2)。
- 变量斜体、单位正体；单位与数值间留 1 个空格。

### 11.3 代码与配置

- 等宽字体（Consolas / 思源等宽）8.5pt，行距 1.3，浅灰底 gray-100 + 0.5pt 描边。
- 单段代码不超过 20 行，超长拆分为多段并标注文件路径。

## 12 六类文档模板

结构模板只规定**区块顺序**，不规定篇幅。任何业务场景取最接近的一类，允许删减带“○”的区块，带“●”的不可删。

| 类型 | 区块顺序 | 必含 |
| --- | --- | --- |
| 研究报告 / 洞察 | 封面● → 摘要● → 目录○ → 正文分章● → 结论建议● → 附录与数据说明● → 免责● | 编号、目录、表题 |
| 方案 / 提案 | 封面● → 背景与目标● → 方案主体● → 实施计划● → 资源与预算○ → 风险与对策● → 附录○ → 免责● | 计划表、里程碑 |
| 合同 / 协议 | 封面○ → 当事人信息● → 条款（第一条…）● → 附件● → 签署页● → 免责● | 页码、骑缝、签署栏 |
| 会议纪要 | 抬头信息表● → 议题与结论● → 待办事项表● → 附件○ → 免责● | 时间、参会人、责任人 |
| 产品手册 / 说明 | 封面● → 目录● → 分章操作说明● → 参数表● → 故障排查● → 免责● | 步骤编号、图题 |
| 财务 / 数据报告 | 封面● → 关键指标● → 分项表格● → 口径说明● → 免责● | 单位、口径、表头重复 |

所有类型的免责声明位置一致：**篇尾（末章之后，全文最后一行）**。**不得因为“内容不需要”而省略**——内容由 AI 起草时更需要声明。

## 13 免责声明（强制）

与网页规范同一句文案、同一套禁令，但**文档只出现一次**：篇尾一句收尾。封面不放。

**唯一位置 · 篇尾 · 末章之后**

短句单起一行，9pt / 加粗 / gray-1200，其上 12pt 空白，并与上方内容用 0.5pt gray-400 通栏细线分开。整块不加底纹、不加边框、不缩进；**其下不再接任何说明段**。

> 内容由 AI 生成，请核实重要信息

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 文案 | 内容由 AI 生成，请核实重要信息 | 中文逗号，句末不加句号；全文仅此一处，逐字一致 |
| 篇幅 | **只有这一句，不写长版** | 篇尾之后不得再出现“本文档由 CeCeMate……”类补充段；口径与局限写进末章数据说明 |
| 位置 | **篇尾 1 句，页脚不放** | 必须是正文最后一段；页脚只留页码，不得再复制这句 |
| 字号 | 9pt | 不得小于 8pt；不得设白色、不得降低不透明度 |
| 色彩 | gray-1200 | 中性灰，**不用蓝色**（蓝只属标题）、不用红色警示——它是事实陈述 |
| 可访问 | 常显 | 不得设为隐藏文字、不得放进批注/尾注、不得作为图片嵌入 |
| 导出 | 随文件 | PDF 导出后仍须可见；打印预览须能读出 |

## 14 DOCX / PDF 实现

以下是把上述规则落到 `.docx` 的技术要点。实现可使用现有文档生成工具，但必须满足本节约束，并在生成后运行本技能的核心结构检查。

| **要点** | **做法** |
| --- | --- |
| 样式而非直接格式 | 定义 Normal / **正文段落** / Heading 1-3 / Caption / TableText 命名样式；正文段落只引用样式，不逐段设字号 |
| 正文缩进 | 在「正文段落」样式的 \`w:pPr\` 写 \`w:ind w:firstLineChars="200" w:firstLine="420"\`（2 字符 / 21pt）；表题、来源、免责、目录、表格单元格继续用 Normal，天然不缩进 |
| 标题加粗 | 样式设 \`w:b\`，每段 run 再写一次 \`w:b\`——只靠样式继承时，WPS / Pages 偶尔丢粗 |
| 中文字体三属性 | 每次设字体都要同时写 \`w:ascii\`、\`w:hAnsi\`、\`w:eastAsia\`，否则中文回退宋体 |
| 主题字体陷阱 | 模板自带的 Heading 1–3 样式带 \`w:asciiTheme\` / \`w:eastAsiaTheme\`，**主题属性的优先级高于显式字体名**——不清掉，标题会继续用主题字体（宋体 / 等线），黑体等于白设 |
| 页码 | 用 \`PAGE\` / \`NUMPAGES\` 域，不手写数字；起始页码 1，封面节排除；**页脚只放页码，不要再复制免责短句** |
| 目录 | 用 \`TOC\` 域并提示“打开后按 F9 更新”；也可直接生成静态目录（推荐，避免空目录） |
| 页眉行业洞察logo | 页眉段落内嵌 inline shape，高度 0.55cm；**不用文本框、不用浮动图形** |
| 封面行业洞察logo | 封面为独立 section，\`different first page\`；行业洞察logo 作为该段 inline 图，高 1.10cm；**该段行距设单倍**（\`w:lineRule="auto"\`），固定行距会把图裁掉 |
| 含图段落行距 | 任何内联图片所在段落都不得用固定行距 &lt; 图高；Normal 是固定 17.3pt，图片段必须显式覆盖为单倍，否则 1cm 以上的图只剩下半截 |
| 表格 | \`w:tblW type="dxa"\`（= 版心 twips）+ **\`w:tblLayout type="fixed"\`**；\`tblHeader\` 重复表头、\`cantSplit\` 防断行；列宽由 \`w:tblGrid\` 一次定死，表头与每行 \`tcW\` 同值（见 §10） |
| 图片 | 宽度取 \`min(原始宽度, 17.18cm)\`、等比缩放、居中；同时设置 \`alt\` 替代文字 |
| 禁止项 | 文本框、SmartArt、艺术字、形状、渐变填充、emoji、嵌入 HTML、跨节浮动图片 |
| PDF 导出 | 嵌入全部字体；保留书签；页面尺寸 A4；不得“按纸张缩放” |

> **WPS / Google Docs 兼容性。** 文本框、SmartArt、形状、页眉色带在跨软件打开时错位率最高。只用“段落 + 表格 + inline 图片 + 域”这四类元素，可在 Word / WPS / Google Docs / Pages 之间保持版式一致。

### 15.1 治空白与分页的断言

页面级的缺陷只能靠页面级的断言拦住。以下 7 条针对“封面丢失、空白页、半空页、空表头、孤页、表头错列”这六类返工最高的排版问题。

| **编号** | **断言** | **判定方式** |
| --- | --- | --- |
| D30 | **无空白页与半空页** | 除末页外每页有效内容 ≥ 版心高度 35%（末页 ≥ 25%）；不足即 FAIL，须改版或增删内容 |
| D31 | **无空段落充间距** | 正文中连续空段落为 0；段间距只能来自样式段后值，不得由空行或连续换行伪造 |
| D32 | **封面独立成页** | 封面为独立 section 且仅 1 页；摘要、目录与封面不同页；封面页无页眉、无页脚、无页码；正文页码从 1 起 |
| D33 | **表头无空单元格** | 表格首行每个单元格均有文本；出现整行空白的表头即 FAIL（空表头比没有表头更糟） |
| D34 | **章末页不孤行** | 章末页正文行数 ≥ 3；只剩 1–2 行判 FAIL，须重新压缩本章或调整图表位置，不得加空行推页 |
| D35 | 表头列宽与数据行一致 | 每张表 \`w:tblGrid\` 的 gridCol 数量与合计（= 版心宽）唯一，且每一行每个 \`tcW\` 都等于对应 gridCol；任一行列宽与表头不同即 FAIL——列宽按行各写一套，正是表头与数值列错位的直接原因 |
| D36 | 表头与同列数据同向对齐 | 逐列比对表头段落 \`jc\` 与该列数据段落 \`jc\`：文本列同为左对齐，数值列同为右对齐；表头居中而数据左 / 右对齐判 FAIL |
