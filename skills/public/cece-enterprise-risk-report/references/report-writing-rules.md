# 企业风险监控报告 · 生成规则

> 用途：对一组企业集合生成风险监控报告（MD → DOCX）。通用口径，不限定特定区域/客户。

## 一、任务定位

对一组企业集合（用户提供名单或上游工具筛定）生成风险监控报告。核心价值：不是数据堆砌，而是"信息汇总 + 分析研判 + 趋势预判"。

报告维度跟着企业集合走：行业分节按企业实际所属行业（不预设固定分类）；区域落地按企业注册地主导区域。

## 二、报告结构（默认）

```
一、报告概述
  1.1 监测说明（周期、来源、覆盖范围）
  1.2 总体监测情况（风险特征/舆情特征/概览表）

二、行业分析（按集合实际行业分布分节；每行业）
  【行业动态】（行业趋势+政策+龙头大事件）
  【区内动态】（集合内企业本期动态+风险研判+落地指向）
  重点企业动态表（企业|细分行业|本期动态|行业研判；仅列有动态企业）

三、重点企业深化分析（按风险条数/等级/舆情热度自动识别的重点企业）
  每家四段式：重要动态（连续文体）+ 股东结构（表格）+ 业务布局 + 风险分析（四步推导）

四、本期企业信号提示
  重点关注 / 积极信号 / 平稳 三类

五、新注册企业追踪（若集合含当月新注册）
  按数量级分级处理：
  - 少量（<100家）：总览 + 特写 top 5-10 家 + 附录全量名录
  - 中量（100-1000家）：总览 + 特写 + 分类统计名录（按行业/区域汇总）
  - 大量（>1000家）：总体画像（数量/行业分布/注册资本分布/重点区域）+ 特写 top N
    + 名录给"重点精选 top 100"，注明"完整名录可提供数据文件"
  ※ 特写永远只挑 top N：按注册资本大/股东背景强/AI关键词/当月有动态筛选
  ※ 新注册追踪的价值是"发现值得关注的增量主体"，大量级时聚焦判断而非罗列

六、总体研判与后续监测建议

附录1：监测企业全量名录
附录2：新注册企业全量名录（若有）
```

## 三、写作口径

1. **研判视角**：关注对企业营收规模、经营稳定性的未来影响，给预警/放量时点判断
2. **落地连接**：每行业、每事件落到"对这批企业/该区域的影响"
3. **判断式语言**："总体判断：积极/重点关注/平稳偏谨慎""风险点：一是…二是…"
4. **数据说话**：关键结论附数据（金额、比例、时间、来源）
5. 重点关注企业须写清传导链（如减资→授信收缩→营收下滑的窗口期）

## 四、动态去重与合并规则（强制）

1. **数据层去重**：sourceId 相同者合并；同企业同类型同案号/标题的记录合并
2. **同日同类型合并**：同日同类型多条记录合并为一条
3. **舆情去重**：同一事件多来源收录的，按"日期+标题"合并
4. 动态列只留事实，**不写"（N条合并）""（来源：xxx）"等过程标注**

## 五、写作质量硬规则（强制）

1. **禁止套话与雷同**：任何两家企业的风险分析/研判结论不得逐字相同
2. **风险分析先还原事件再下判断**：禁止"上述事件"式指代不明；"重点关注"判定必须有事实链支撑
3. **动态列=连续事实句**：时间+事件+当事人+金额/案号，禁止字段标签堆砌（"案由：""开庭日期："等改写进句子）
4. **研判列=事实+含义**：分类计数（开庭/专利/被执行/变更分开计数，**专利不计入开庭/涉诉**）
5. **行业研判差异化**：各行业落到该行业集合内企业的本期实际动态，禁止方法论式通用结论
6. **金额带单位**（万元/亿元），禁止无单位裸数字
7. **用词口径**：报告用语一律"重点关注"；数据侧高/中/低风险分级表述不变
8. **原始数据清洗后入报告**：多余空格/换行/字段标签前缀清除

## 六、分析框架（强制）

### 风险分析（重点企业）
四步推导：**①事件还原**（时间/事件/金额/案号）→ **②影响判断**（影响企业什么能力）→ **③传导路径**（对产业链/营收/就业哪个环节）→ **④处置建议**（可执行动作）。缺一步视为未完成。

### 行业分析
【行业动态】写清趋势背后的驱动因素（政策/市场/技术/资本）+ 当月真实数据/政策/事件；【区内动态】落到集合内企业的本期实际动态+风险研判+落地指向。

### 联网检索
行业动态与重要事件须基于当期真实检索结果（具体政策名、数据、事件、时间、来源）。**无联网能力时不得用模板化句式填充，必须确保数据真实、有来源**，应由人工提供素材包。判断标准：每个行业的动态段至少含 1 个具体数据或具名事件。

## 七、生成流程：写两遍 + 双层自检

1. 第一遍：按结构与数据出草稿
2. 第二遍：以"挑刺编辑"身份逐段自评审——这段有没有具体事实？有没有明确判断？有没有增量信息？三缺一则重写
3. 转换生成 docx 后跑代码体检（格式/残留）
4. **大模型通读自检**：按《自检清单》逐条核对全文，两层都过才交付

## 八、禁忌清单（违反即返工）

1. 正文禁止 Heading 样式；标题禁止漏标样式
2. 标题不含工程注释或过程性表述
3. 正文及标题不出现内部字段名与过程信息（company_id、接口名、"待补"占位符）
4. 章标题不重复；同一编号不用两次
5. 统计数字以数据实际为准，不凭记忆填写
6. 企业名不带尾部标点（"XX有限公司。"）
7. 表格无空表头；空字段（原告/案由/金额为空）整段省略，禁止"原告：，"类空标签
8. 股东表数据必须取数得到，禁止"详见工商登记"占位
9. 行业表格必须按集合内企业实际数据生成，禁止手写概括
