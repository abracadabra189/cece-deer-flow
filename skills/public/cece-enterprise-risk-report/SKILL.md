# 企业风险监控报告生成器

对一组企业生成风险监控报告（Markdown 分析稿 → docx 交付件）。本技能负责业务逻辑与报告生成；**业务数据只有一个来源：CECE HYDC 取数通道**（`cece-hydc-data` 技能的 `hydc.mjs` wrapper，命令口径见 `references/hydc-command-map.md`）。不直连任何外部接口，不接触密钥，不用模型自带知识充当业务事实。

## 前置条件（开工前自检，任一不满足就停下说明，不要绕道找替代取数方式）

| 前置条件 | 自检方式 | 不满足时的处置 |
|---|---|---|
| 沙箱可执行命令 | `bash` 工具可用 | 告知"当前部署未开放沙箱命令执行，无法取数"，中止 |
| HYDC 取数技能在位 | `read_file /mnt/skills/public/cece-hydc-data/SKILL.md` 成功 | 告知缺失的技能名，中止 |
| HYDC 凭据已由运维注入 | 执行一次 `node /mnt/skills/public/cece-hydc-data/scripts/hydc.mjs help`，返回命令清单 | 若返回 `HYDC_API_KEY is not configured` 或鉴权失败：原样转告"HYDC 凭据未配置或无效，需运维在部署环境注入"，中止。**不得**向用户索要密钥，不得把密钥写进命令、文件或输出 |
| docx 渲染能力（仅需交付 docx 时） | `python3 -c "import docx"` 无报错 | 降级交付 Markdown，并说明"当前沙箱缺少 python-docx，已交付 MD；需要 docx 请让运维在沙箱镜像中安装" |

自检每次会话只做一轮；已确认过的命令与参数不重复 `help`。

## 取数通道：唯一且不可替换

只用 HYDC wrapper，命令与参数按 `references/hydc-command-map.md`：

```bash
node /mnt/skills/public/cece-hydc-data/scripts/hydc.mjs help
node /mnt/skills/public/cece-hydc-data/scripts/hydc.mjs query "<业务命令>"
```

该映射表是**当前口径**；具体命令、参数与返回字段以 `help` 返回的 schema 为准，不臆造命令名、参数名或字段名。wrapper 只接受 `help` / `query` 加业务命令，端点、超时与凭据由运维控制，不接受也不得传入覆盖参数。

**本平台已关闭或不适用的取数方式，一律不得尝试**：

- 企业/产业/金融/人物类 MCP 工具（本部署不再使用）
- 公网检索与网页抓取类工具、浏览器自动化
- 自行构造 HTTP 请求或调用任何外部接口
- 用模型预训练知识、记忆或"行业常识"填充业务数据

数据拿不到时的唯一正确动作：**如实标注"数据缺失/取数失败"及具体环节与企业**，不用推测补齐（见"错误处理""分析边界"）。

## 适用边界（正向界定）

**本技能只做一件事**：对一组企业生成风险监控报告（交付型文档）。

- 触发信号：用户要求"生成/出/做一份企业风险监控报告、风险报告、监控月报"等交付型文档
- 除此之外的意图（查企业、问情况、产业问答、筛选罗列企业）均**不属于**本技能，走常规问答

## 交互原则：能默认就默认，不打断用户

| 参数 | 默认 | 说明 |
|---|---|---|
| 企业集合 | 前文/附件已有名单或筛选规则→直接用 | **仅当完全没有时**提示一次：请提供名单或筛选条件 |
| 监控周期 | 当月（月度口径） | 不打断；用户指定周期则用其指定；默认时提示"当前按月度口径，需要其他周期可更新" |
| 输出形式 | docx | 不打断；先出 MD 分析稿再转 docx；用户指定 html 等则按其指定，改用对应制品技能，不在本技能里造第二套渲染 |
| 企业规模 | ≤200 家逐家分析；>200 家默认整体画像+聚合统计 | 见下"规模引导" |

**企业集合理解有歧义时**才复诵确认一次，否则直接执行。

## 企业集合的来源

本技能自"拿到企业集合"开始。集合来源开放：

- 用户提供的名单（附件/前文）
- 上游按筛选条件（区域/产业/被投资/融资过等）筛定的企业集

本技能**不负责企业筛选**；筛选由上游完成。

## 规模引导（>200 家时）

默认给"整体画像+聚合统计"，并提示用户：

> "当前范围较大（N 家）。已为您生成整体画像；可缩小范围（按行业/区域收敛），或点名重点关注的企业做深度分析。"

用户点名深度分析的企业，再做逐家取数与深化。

## 工作流程

```
1. 前置自检  按"前置条件"表逐项确认（bash / HYDC help / docx 能力）
2. 定集合    企业名单（用户提供）或上游筛定的企业集
3. 集合画像  统计集合的注册地分布、行业分布，反推报告的区域与行业组织维度
             （用户给了区域/行业入参则用入参；没给则从企业数据反推；
              跨区域集合按主导区域落地、其他区域单列）
4. 取数      按 references/hydc-command-map.md 逐步取数，分片落盘
5. 组装素材  企业→行业分组→事件/股东/舆情汇总
6. 识别重点  按企业风险条数/风险等级/舆情热度自动识别重点企业（用户点名时优先）
7. 分析生成  按 references/report-writing-rules.md 的框架写报告（MD）
8. 转换      MD → docx（新华社公文格式，见 references/docx-format-spec.md）
9. 自检      按 references/self-check-list.md 通读核对，通过才交付
```

**报告维度跟着集合走**：行业分析按企业实际所属行业分节（不预设固定行业分类）；"对我区影响"按企业注册地主导区域落地。

## 报告结构与配套规则

默认结构：概述（监测说明 + 总体监测情况）→ 行业分析（每行业：行业动态 + 区内动态 + 重点企业动态表）→ 重点企业深化（每家四段式）→ 信号提示（重点关注 / 积极 / 平稳）→ 新注册企业追踪 → 总体研判 → 附录1 监测名录 / 附录2 新注册名录。

四份配套规则各司其职，写作与自检时按需查阅：

- `references/hydc-command-map.md`：取数命令与字段口径（唯一取数通道）
- `references/report-writing-rules.md`：报告框架、写作口径、动态去重合并、禁忌清单与深度分析要求
- `references/docx-format-spec.md`：docx 页面、字体、标题层级与表格样式（新华社公文格式）
- `references/self-check-list.md`：交付前逐项核对清单，**未通过不交付**

## docx 生成方式（当前环境可用手段）

- 在沙箱工作区按需写一次性 Python 脚本，用 `python-docx` 按 `references/docx-format-spec.md` 的页面、字体、标题层级与表格样式渲染 MD 内容；脚本与中间产物放 `/mnt/user-data/workspace`，成品放 `/mnt/user-data/outputs`。
- 沙箱未安装 pandoc，不要依赖它；也不要手工拼接 docx 二进制。
- 生成后只做一次结构校验（文件存在、非空、能被 python-docx 重新打开）；排版细节问题最多修一次，不反复重跑整篇。
- 交付时用 `present_files` 把成品暴露给用户。

## 断点续跑

大报告分片落盘，中断后从断点续：

- 取数层：企业分片取数，结果存 `processed/events_分片N.json`，进度记 `progress.json`
- 生成层：分章写 MD
- 重跑时跳过已完成分片与章节

## 错误处理

- **前置条件不满足**（无 bash / HYDC 技能缺失 / 凭据未配置）：按"前置条件"表原文说明缺什么、由谁补，然后中止；不要改用其他取数方式，也不要凭记忆写报告
- **取数全部失败**：报出失败命令与返回原因并中止
- **部分失败**：照常生成，交付时注明缺失的具体企业名单与环节，询问是否重试补缺
- **命令不熟**：先 `help` 查 schema，不臆造命令与字段
- **空结果**：视为"该口径下无记录"，写明查询条件与时间范围，不等于"无此企业/无此事"

## 分析边界

- 事实与推断分开，标注数据口径与时间范围
- 缺数据就明说，不用推测填充
- 空结果/报错视为数据限制，不等于"无此企业/无此事"
- 报告中不得出现内部字段名、接口名、company_id 等技术占位（见 `references/self-check-list.md`）
