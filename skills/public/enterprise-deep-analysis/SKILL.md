# CECE 企业深度分析

## 定位

用已配置的企业、主体识别、产业、人物与创投融资 MCP 数据，完成可追溯的中国企业深度研究。报告的价值不在于堆砌工商字段，而在于把已核验的事实转化为有边界的分析判断。

本 Skill 采用 Anthropic 发起覆盖研究（initiating coverage）的五段式工序：**公司研究 → 财务/资本建模 → 估值与情景 → 图表 → 报告组装**。CECE 的版本以自有 MCP 数据为第一证据源；没有充分数据时降低结论粒度，而不是以模型记忆补齐。

## 适用边界

优先使用本 Skill：

- “给我做 XX 的企业画像 / 企业全景报告 / 企业尽调”。
- “分析 XX 的发展前景、成长性、竞争力、投资价值或战略位置”。
- “比较 XX 与竞品 / 同行业公司的差异与机会”。
- “分析 XX 的产业链位置、资本路径、经营风险、扩张能力”。
- 需要结论、依据、风险和行动建议的企业研究任务。

不要使用本 Skill：

- 仅问法人、注册资本、地址、一个股东、一次融资、某高管等单一事实。
- 仅要一个企业列表或按条件筛选企业。
- 仅需把已有材料改写、翻译或排版。

这类轻量问题交给 `enterprise-qa`。如果同一提问同时含单一事实和深度研究目标，以本 Skill 为主，但仍遵循最小必要调用原则。

## 总原则

1. **先识别，后检索。** 用户给出简称、品牌名、股票简称或模糊名称时，先用 `entity_resolve` 的企业检索能力确认工商登记全称、主体标识与候选项；不可猜测全称。
2. **自有数据优先。** 企业事实优先取自 `enterprise`、`entity_resolve`、`industry`、`person`、`pevc` MCP。实时新闻、政策或市场背景有明显数据缺口时，才把联网搜索作为补充，并在文中标注来源性质。
3. **事实、分析判断、待验证严格分层。**
   - **事实**：工具或用户材料直接返回，写明来源和时间线索。
   - **分析判断**：由两个及以上事实推出，使用“表明 / 可能 / 倾向于”，写清推理链。
   - **待验证 / 数据缺口**：当前工具无返回、返回失败、时效不明或关键指标缺失时明确列出；不得编造。
4. **失败不是无数据。** MCP 的超时、权限、参数错误、404/406、工具异常，与“检索无数据”分开陈述。
5. **不伪造财务与估值。** 只有 MCP 或用户上传资料给出可核验口径时，才能计算收入、利润、估值、倍数、市场份额或排名。否则输出定性情景，不输出虚构数字。
6. **不做投资承诺。** 发展前景、投资价值和风险属于研究判断，不构成投资建议。

## 全量 MCP 深度研究协议

对于 L2 前景研判和 L3 深度报告，必须覆盖**所有已启用的企业研究 MCP**，不能因为首轮结果已经足以写一段摘要就提前结束。当前 CECE 的标准覆盖面如下：

| MCP 服务 | 最小研究任务 | 进入报告的证据位置 |
| --- | --- | --- |
| `entity_resolve` | 主体消歧；产业、区域或标准分类映射 | 主体确认、研究边界 |
| `enterprise` | 基本信息、标签/资质、股权、管理层、对外投资、招投标和关系线索 | 企业画像、治理、商业化、风险 |
| `industry` | 与目标公司业务相符的产业链、赛道或产业观察 | 行业位置、竞争与增长驱动 |
| `person` | 仅查询与战略、治理、融资或业务关键相关的核心人物 | 治理与组织能力 |
| `pevc` | 融资、基金、同业融资或产业资本可比线索 | 资本能力、同业对比、扩张信号 |
| `qwen-enhanced-search` | 最新新闻、公告、政策、市场事件或公司公开动态交叉验证 | 时效补充、外部催化剂与风险 |

### 覆盖执行规则

1. 先取得明确企业主体，再规划六类 MCP 调用；同一轮中允许并行调用互不依赖的服务。
2. **每个 MCP 服务至少**执行一次与研究命题直接相关的工具调用；若服务没有适用工具、返回无数据或调用失败，也必须在证据台账中记录服务名、工具名、状态和原因。
3. `qwen-enhanced-search` 是外部时效交叉验证，不得覆盖或替代企业 MCP 的工商、股权、融资和人物事实。
4. 如用户明确要求“仅使用内部数据”，仍调用前五个内部 MCP；将 `qwen-enhanced-search` 标记为用户限制而未调用。
5. L1 快速画像可以按最小必要工具调用，不强制六服务覆盖；但用户要求“完整画像”“深度报告”“发展前景”时自动升级到 L2 或 L3。
6. 不得为了凑全量覆盖而捏造工具输出、重复相同查询，或把不相关人物、基金、行业结果拼接进报告。

### 全量证据台账

每份 L2/L3 报告先形成下面的覆盖台账；任何未覆盖项都必须在最终“数据缺口与后续核验清单”中解释：

| MCP 服务 | 工具 / 查询目标 | 状态 | 提取事实或空结果 | 对分析的作用 |
| --- | --- | --- | --- | --- |
| entity_resolve | … | 成功 / 无数据 / 失败 / 用户限制 | … | 主体、行业或区域标准化 |
| enterprise | … | 成功 / 无数据 / 失败 | … | 企业、股权、业务或项目事实 |
| industry | … | 成功 / 无数据 / 失败 | … | 产业与竞争背景 |
| person | … | 成功 / 无数据 / 失败 | … | 治理与关键人判断 |
| pevc | … | 成功 / 无数据 / 失败 | … | 资本与可比线索 |
| qwen-enhanced-search | … | 成功 / 无数据 / 失败 / 用户限制 | … | 最新外部验证 |

## 输入澄清与研究等级

先从用户请求中抽取：企业、研究目的、观察期、目标地区、行业/竞品、读者对象、篇幅与交付格式。

| 研究等级 | 典型请求 | 默认交付 |
| --- | --- | --- |
| L1 快速画像 | “企业画像”“介绍并判断特点” | 结构化画像 + 3–5 条判断，优先完成阶段一、三、五 |
| L2 前景研判 | “发展前景如何”“是否值得关注” | 完整五阶段的精简报告，含情景、风险、建议 |
| L3 深度报告 | “尽调 / 竞争格局 / 投资研究 / 专题报告” | 完整五阶段、证据台账、竞品比较、图表与附录 |

缺少企业名称且无法可靠消歧时，只问一个最小问题：请用户确认目标工商主体。其他信息缺失时，先按 L2 的默认口径推进，并在开头声明范围与假设；不要因可选字段缺失而反复追问。

# 五段式工序

## 第一阶段：主体确认与研究命题（公司研究）

### 目标

确认“研究谁、研究什么、以什么时间和口径判断”，避免把不同主体、同名企业或集团母子公司混在一起。

### 必做动作

1. 用 `entity_resolve` 查询用户给出的名称。保留候选的工商全称、主体标识、地区和行业线索。
2. 候选超过一个且无法根据上下文排除时，展示候选并请用户确认；不能静默挑选。
3. 用 `enterprise` 的基本信息、标签/资质能力建立企业底档；记录数据更新时间或查询日期。
4. 明确研究命题，至少覆盖下列之一：成长性、竞争力、产业位置、资本路径、治理能力、风险、区域价值或合作价值。
5. 生成“研究边界”小节：主体、截至日期、数据范围、未覆盖内容。

### 第一阶段输出门槛

在没有拿到确定企业全称前，不可调用依赖企业全称的深层企业工具。完成后先在内部形成：

```text
主体：工商登记全称（主体标识）
命题：例如“未来 12–24 个月的增长驱动与主要制约”
范围：截至日期、地区、行业、是否纳入集团/子公司
需要验证：业务基础、资本/融资、产业竞争、治理/人物、风险
```

## 第二阶段：证据采集与数据包（财务/资本建模）

### 目标

围绕研究命题建立最小充分证据包，而非无差别调用所有工具。企业经营、资本和关系数据共同构成“财务/资本建模”的可用底座；没有财务报表时，不能把工商数据伪装成财务分析。

### 证据矩阵

| 维度 | 优先 MCP | 建议核验内容 | 适用的分析问题 |
| --- | --- | --- | --- |
| 主体与业务 | `entity_resolve`、`enterprise` | 基本信息、经营范围、标签、资质、荣誉 | 做什么、能力边界、业务方向 |
| 股权与控制 | `enterprise` | 股东、对外投资、企业关系图 | 控制权、集团协同、扩张路径 |
| 治理与关键人物 | `enterprise`、`person` | 法定代表人、董监高、核心人物画像 | 决策稳定性、资源能力、关键人风险 |
| 资本与融资 | `enterprise`、`pevc` | 股权融资、银行/股票融资、竞品融资 | 融资节奏、资本支持、同业热度 |
| 商业活跃度 | `enterprise` | 招投标、业务/融资关系图等已返回数据 | 客户/项目线索、商业化迹象 |
| 产业与区域 | `industry`、`entity_resolve`、`pevc` | 产业链、产业标签、区域、产业基金 | 行业位置、区域承接能力、政策/资本土壤 |
| 时效补充 | 联网搜索（可用时） | 最新公告、新闻、政策、实时市场信息 | 仅补足时效性缺口 |

### 调用规则

- 企业简称、品牌名、集团名：先主体识别，再调用企业工具。
- 多工具请求：先完成主体确认；随后可并行采集互不依赖的证据。
- `pevc` 需要产业或区域标准编码时，先通过 `entity_resolve` 获取标准值。
- 只在“竞争 / 融资对比”确有必要时调用竞品融资工具；无结果时不反复盲试。
- 人物工具只用于与企业研究命题有关的核心人物，不为凑篇幅逐个查询。
- 所有关键结论至少记录一条可回溯的 MCP 来源；金额、日期、比例保留原始币种、单位和口径。

### 证据台账

在内部维护，最终摘要化呈现：

| 编号 | 事实 | 来源 | 时间/口径 | 对结论的作用 | 可靠性 |
| --- | --- | --- | --- | --- | --- |
| E1 | … | enterprise MCP | 返回日期/更新日期 | 支撑业务定位 | 高 |
| E2 | … | pevc MCP | 事件日期 | 支撑资本路径 | 中/高 |
| G1 | 数据缺口或工具失败 | 工具名称 | 查询日期 | 限制某项判断 | — |

“可靠性”按来源直接性、时间性、是否完整而定，不等同于企业好坏。

## 第三阶段：经营与竞争分析（公司与行业推理）

### 目标

把第二阶段的数据包转换成明确、有依据、可反驳的判断。每一条核心判断至少应当对应两类证据，或明确说明只有单一来源。

### 六维分析框架

1. **定位与业务模式**：主营方向、产品/服务、资质标签、产业链环节、客户/项目线索。
2. **增长引擎与扩张能力**：对外投资、业务拓展、融资节奏、区域布局、产业资源；没有收入数据时，使用“扩张信号”，不用“业绩增长”。
3. **治理与组织能力**：股权结构、关键管理层、关键人物经历、控制权集中度与关键人依赖。
4. **资本能力与资源协同**：融资记录、投资方/基金、银行或资本市场线索、被投与对外投资网络。
5. **产业竞争与差异化**：行业标签、同业融资/项目线索、竞品可比数据；比较必须限定样本范围和可比维度。
6. **风险与约束**：数据反映的股权、融资、经营、合规、技术替代、区域依赖、客户集中或关键人风险；工具没有提供的风险不可断言为已发生事实。

### 推理写法

每个核心结论采用固定形状，避免空泛：

```markdown
**判断：** （清晰结论，带不确定性强弱）

**依据：** （E1 事实）+（E2 事实）。

**推理：** （为何这些事实支持此结论；不跨越数据边界）。

**限制：** （缺什么数据，结论在哪些条件下不成立）。
```

禁止把“存在融资”直接推出“经营优秀”，把“有标签/资质”直接推出“市场领先”，把“竞品无数据”直接写成“无竞品”。

## 第四阶段：情景、估值与图表（估值与可视化）

### 目标

用图表和情景使判断可读、可审阅。这里的“估值”是一个严格受数据约束的模块：可做有口径的相对比较，也可只做定性价值驱动/情景矩阵。

### 情景与估值规则

1. 先列出价值驱动：行业景气、产品/资质、客户项目、融资能力、治理执行、区域资源等。
2. 以基准、乐观、审慎三种情景展示触发条件、上行因素、下行因素和可观察指标。
3. 只有在可核验财务、交易或估值数据齐备时，才计算估值倍数、增长率、现金流或量化区间；所有公式、单位、期间、样本和假设必须列明。
4. 数据不足时，输出“定性估值 / 关注优先级”，不得输出看似精确的价格、估值或市场份额。

### 图表规则

- L2/L3 的默认交付物是一个**交互式 HTML** 企业研究仪表板，而不仅是聊天中的 Markdown。只有用户明确说“不生成文件”时才省略。
- 使用 AIO 沙箱镜像中**预装**的 Plotly 生成独立 HTML；不在任务运行时扫描或安装绘图库。图表数据必须来自证据台账或用户上传文件，禁止手工补值。
- 仪表板必须包含**至少三类图表**，并按实际返回的数据从下列中选择：融资时间线、股权/投资关系网络、竞品融资对比、产业链位置、区域/产业分布、关键人物关系、情景矩阵、风险热力图。数据不足导致某类图表无法生成时，以“数据缺口”卡片替代，不能造图。
- HTML 至少包含“执行摘要、MCP 覆盖台账、图表总览、核心判断、情景与风险、数据缺口、来源说明”七个可导航区块；图表须支持悬停查看数据，且标题、单位、口径、来源、日期可见。
- 文件必须写入 `/mnt/user-data/outputs`，使用唯一文件名，例如 `企业简称_深度研究仪表板_YYYYMMDD_HHMMSS.html`。写入前先读取同名目标；写入后用 `read_file` 或等效校验确认存在、再把制品路径和下载链接交给用户。

## 第五阶段：报告交付与复核（报告组装）

### 交付结构

L2/L3 默认按下列结构输出；L1 可压缩但不省略数据边界与风险：

```markdown
# 企业全称：企业深度分析

## 一、执行摘要
- 企业定位：
- 核心结论：
- 前景判断：积极 / 审慎积极 / 中性 / 审慎，及置信度。
- 最重要的三项机会与三项风险：

## 二、研究范围与数据说明
- 主体、截至日期、数据来源、数据缺口。

## 三、企业画像
- 基本底档、业务与产业位置、股权与治理、资本与扩张线索。

## 四、核心分析
- 增长引擎、竞争位置、资本能力、组织治理、风险约束。
- 每节使用“判断—依据—推理—限制”形状。

## 五、发展前景与情景
- 基准 / 乐观 / 审慎情景、触发条件、观察指标。

## 六、行动建议
- 面向用户目标给出可执行的跟进、合作、尽调或监测建议。

## 七、数据缺口与后续核验清单

## 附录：关键事实与来源

## 交互式 HTML 制品
- 制品路径：`/mnt/user-data/outputs/企业简称_深度研究仪表板_YYYYMMDD_HHMMSS.html`
- 说明：图表、MCP 覆盖状态与数据缺口均已写入仪表板。
```

### 交付前复核清单

- 已确认主体，且工商全称未被简称替代。
- 事实、分析判断、待验证 / 数据缺口已分层。
- 每个重要结论都有来源和推理；没有把失败写成无数据。
- 金额、时间、比例、单位与原始口径一致。
- 没有基于缺失数据虚构财务、估值、排名、客户或风险事件。
- 联网信息（如使用）与自有 MCP 事实已清楚区分。
- 图表只使用可回溯数据，文件名唯一且制品可访问。
- L2/L3 已调用所有已启用的企业研究 MCP，或已明确记录某服务无数据、失败或受用户限制。
- 已生成并校验交互式 HTML；其中至少三类图表或相应的数据缺口卡片可见。
- 结论的置信度匹配证据完整度。

## MCP 不可用时的降级方式

- `entity_resolve` 不可用：说明无法确认主体，不对同名企业作深度结论。
- `enterprise` / `pevc` / `industry` / `person` 任一不可用：继续使用其余来源，但将对应维度列为数据缺口，降低置信度。
- 联网搜索不可用：只使用企业自有数据完成报告，不以“最新”描述不可核验的信息。
- 所有关键数据源不可用：只输出研究框架、需补充数据清单和下一步查询计划，不输出企业事实或发展结论。

- “请给兆易创新做一份企业画像，并分析未来两年的发展前景。” → 使用本 Skill。

- “列出上海近一年 AI 产业获得融资的企业。” → 使用 `enterprise-qa` 或 PEVC 筛选流程。
